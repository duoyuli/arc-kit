# arc-kit 工程文档建库与恢复

只有用户要求建立、接入、恢复或重整工程文档库时进入此流程。重写本技能、普通代码修改或发现 `docs/` 缺失，都不自动包含首次建库。

## 确定范围与起点

先按技能入口检查 `docs/index.md` 和 `docs/.project_doc_bootstrap.md`，再读取 [仓库导航](repository_map.md)、[文档维护协议](library_protocol.md)；计划使用锚点时读取 [锚点协议](anchor_protocol.md)。已有明确建库授权时直接推进范围内的目录、正文和引用维护，不重新索取同一授权。

以当前工作区为证据，检查适用的 Agent 指令、Cargo workspace、相关源码及测试、双语 README、贡献入口和实际存在的内置资源说明。保留用户既有修改，遵守当前分支约束。`target/`、本地 `.arc-cli/` 状态、个人 `arc.toml`、凭据与生成文件不作为待纳入的工程文档。

如果备忘录已存在，先与当前文件和差异核对，再从“下一步”继续。缺少根目录但备忘录可用时，使用其目录计划恢复入口。普通任务遇到备忘录仅参考相关内容，不自动接手全部建库工作。

## 规划实际需要的目录

默认使用本技能约定的 `docs/`，工程正文使用中文。保留 README 与 CONTRIBUTING 的原名、位置和双语关系；新文档通过链接引用这些用户入口。

根据当前模块和契约选择主题，以下是候选范围，不是必须创建的文件清单：

| 分类 | arc-kit 中适合持久记录的知识 | 核实入口 |
| --- | --- | --- |
| `architecture/` | 三个 crate 的边界、入口调用关系、来源到安装目标的数据流 | Workspace、crate 入口、registry、安装服务和 CLI 分发 |
| `domains/` | Skill 来源优先级、安装归属、项目声明协调、agent 能力差异 | `arc-core/src/models.rs`、`arc-core/src/skill/`、`arc-core/src/project/`、`arc-core/src/agent/` 及契约测试 |
| `interfaces/` | `arc.toml`、provider profile、CLI JSON、安装台账和 Journal 等独立契约 | 解析器、序列化模型、原生配置映射与黑盒测试 |
| `operations/` | 台账迁移、逐目标事务恢复、故障定位、发布与 Homebrew 更新 | `arc-core/src/skill/install/`、`arc-core/src/io.rs`、恢复测试、发布 workflow 与 Formula |
| `decisions/` | 有证据支持且需要保留理由和取舍的设计决策 | 用户确认的决定或可核实历史，不从现状编造 ADR |

为实际需要的每篇文档确定范围、读取时机、来源与相关测试。先覆盖当前任务中的关键边界，再按用户要求扩展；不为了凑齐分类生成空文档。只有主题、受众和演进周期不同才拆篇。

对现有材料选择保留并引用、纳入、更新、合并或拆分。README 默认保留并引用；迁移其中工程细节时，保持用户说明完整并同步双语链接。涉及删除仍有消费者的材料或无法确定范围的迁移时，先完成可以核实的部分，再澄清具体问题。

## 建立入口和备忘录

使用 [目录模板](../assets/index.md) 创建根入口与实际需要的分类目录。使用 [备忘录模板](../assets/project_doc_bootstrap.md) 创建 `docs/.project_doc_bootstrap.md`，记录范围、工作区基线、计划、依据和下一步。

目录和备忘录应先于批量正文存在。计划文件尚未创建时写成代码格式的路径，不创建失效链接，也不创建只有标题的占位正文。

根入口建立后，同步 `README.md` 与 `README.zh-CN.md` 的文档职责说明：README 保留用户与开发入口，`docs/` 承载跨模块工程契约，并在两份 README 中链接新入口。核对注释语言与 `AGENTS.md` 一致，避免建库后仍留下相互冲突的文档规则。

状态含义：

- `planned`：已确定范围和来源，尚未撰写。
- `in_progress`：正在核实或撰写。
- `verified`：正文、目录、引用和所需锚点均已核实。
- `blocked`：缺少具体依据或存在明确阻塞，记录继续所需条件。

每完成一个工作单元更新备忘录；中断或交接前记录可直接执行的下一步。备忘录用于恢复工作，不用它宣称未运行的测试已通过。

## 核对技能门禁

当前仓库已有根 `AGENTS.md`。门禁负责要求会话加载技能；已建库、建库中和未建库的目录路由统一由 `SKILL.md` 维护。在接入范围内维护 `## Project Doc 门禁`，保留其他协作规则。不要为了建库创建新的分支或无关的 Agent 配置文件。

需要修复门禁时保持以下语义，使用实际技能路径；不再把技能内的目录状态分支复制到项目指令：

```markdown
## Project Doc 门禁

本仓库在 `.codex/skills/project-doc/` 提供 `project-doc` 技能。磁盘上存在技能目录不代表当前 Agent 会话已经加载该技能。

- 执行任何仓库任务前，先确认当前 Agent 会话能够调用名为 `project-doc` 的技能。
- 如果不能调用，立即停止；不得读取业务文件、运行仓库命令、执行分析或修改文件。只回复：“当前环境未安装或未加载 `project-doc` 技能，按仓库规则无法继续。请安装或启用该技能，并在新会话中重试。”
- 如果能够调用，先使用 `project-doc`。
```

门禁章节从该 H2 到下一个 H2 或文件结尾。已有章节原位维护，重复章节合并为一个，缺失时才补充。其他实际存在的 Agent 入口仅在本次接入范围涉及它们时更新，不默认创建整套入口或兼容技能。只读审计报告问题，不写入修复。

检查技能文件的实际内容、Git 跟踪状态与会话可用性；不能因为文件在本机存在就断言它已随仓库共享，是否纳入版本控制不由建库流程自行决定。

当前 `.claude/skills` 是指向 `../.codex/skills` 的符号链接；两个 Agent 入口共享 `.codex/skills/project-doc/`。接入检查按实际路径去重，保留链接。当前 `.codex/`、`.claude/` 均未被忽略，确认是否已跟踪时同时检查目录内容与链接条目。

## 分批核实与撰写

按依赖选择完整工作单元，通常先写系统边界，再写领域、接口与恢复流程。

1. 将当前项标为 `in_progress`，阅读其来源、调用方与测试，确认真实契约及例外。
2. 撰写范围明确的当前状态文档，链接证据入口和相关说明；不抄录完整源码或 README。
3. 为需要从代码跳转的章节添加稳定 ID，在真正的语义入口放置选择性锚点。没有必要的入口时可以不添加。
4. 更新规范目录条目、普通链接，以及确有变化的 README 双语章节和实际存在的资源说明。
5. 核实路径、ID、内容与命名，记录实际验证结果，再将该项标为 `verified`。

保持每批成果可检查；不能先生成全库猜测内容再统一标为已验证。

## 恢复与完成

恢复时以备忘录和当前文件共同判断进度。重新核实有变化的来源和遗留 `in_progress` 项，保留仍有效的已完成结果。范围改变时更新目录计划并写清理由，不为了结束任务静默删去未完成项。

完成建库前确认：

- 约定范围内的所有文档均已核实，没有未解释的计划项或阻塞。
- 根目录和分类目录可路由全部库成员，每篇正文有唯一规范条目。
- 链接、代码证据路径和实际锚点有效，文件名与显式 ID 合规。
- README 的双语用户入口完整，文档职责、工程入口与注释语言和项目指令一致；工程正文没有把规划或工作区变更写成已发布能力。
- 项目门禁路由至技能，技能中的文档入口与实际目录一致，实际执行的验证有记录。

完成检查后清除目录中的临时状态，删除备忘录并修复指向它的链接。尚有工作时保留备忘录，交付具体剩余范围和下一步。纯建库不要求运行无关业务命令，验证仍按文档维护协议选择。
