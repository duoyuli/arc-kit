# arc-kit 工程文档目录模板

首次建库或新增分类时，从下面选取一个变体。替换 `{{...}}` 占位符，删除没有实际内容的节；计划路径用代码格式表示，目标存在后再写成链接。仓库内路径按输出文件的位置调整。

## 根目录变体：docs/index.md

~~~markdown
# arc-kit 工程文档

本目录记录需要跨模块理解的工程知识。每个仓库任务加载 `project-doc` 后先完整读取本文件，再按“读取时机”进入相关文档。

## 范围与用户入口

{{已核实的覆盖范围，以及尚未覆盖的范围。}}

产品用法、命令参数、JSON 和开发流程见 [English README](../README.md) 与 [中文 README](../README.zh-CN.md)。贡献入口见 [English CONTRIBUTING](../CONTRIBUTING.md) 与 [中文贡献指南](../CONTRIBUTING.zh-CN.md)。

## 根级文档

- [{{根级文档标题}}]({{根级文档文件}})：{{一句话范围}}。读取时机：{{相关任务或概念}}。

## 分类

- [{{分类标题}}]({{分类目录}}/index.md)：{{本分类的知识范围}}。读取时机：{{命令、模块、契约或工作流}}。

## 建库状态

<!-- 只在建库期间保留本节；完成后删除本节与备忘录。 -->
- 进度和恢复入口：`.project_doc_bootstrap.md`。
- [planned] `{{计划路径}}`：{{范围与读取时机}}。
~~~

从 `architecture/`、`domains/`、`interfaces/`、`operations/`、`decisions/` 选择实际需要的分类；根级文档也按实际需要添加。不要把所有候选分类原样列入入口。

## 分类目录变体：docs/分类/index.md

~~~markdown
# {{分类名称}}文档

上级目录：[工程文档](../index.md)。

## 范围

{{本分类拥有的知识；与相邻分类的分工。}}

## 文档

- [{{文档标题}}]({{文档文件}})：{{一句话范围}}。读取时机：{{相关命令、模块或契约变更}}。

## 建库状态

<!-- 只在建库期间保留本节；正文创建后将条目移入“文档”。 -->
- [planned] `{{计划文件}}`：{{范围与读取时机}}。
~~~

每篇正文只在一个目录拥有规范条目；其他分类通过普通相关链接引用它。读取时机应能直接路由真实任务，例如“修改 project apply/clean、agent 选择、接管或 dry-run 时”，避免只写“需要了解时”。
