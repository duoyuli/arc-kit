# Project Doc · arc-kit

让工程文档准确描述当前工作区中的实现、跨模块约束和用户契约。此技能是 arc-kit 的仓库协作入口；代码与测试提供核实依据，README 提供用户说明，`docs/` 在建立后承载需要跨文件理解的工程知识。

## 进入任务

1. 遵守根级及任务路径下的 `AGENTS.md`。当前会话已加载此技能才满足技能可用条件；磁盘上存在同名目录不等于已加载。
2. 先尝试读取 `docs/index.md`，按实际状态选择入口：
   - **目录存在**：完整读取根目录，再按“读取时机”读取相关分类和章节。
   - **建库备忘录存在**：补读 `docs/.project_doc_bootstrap.md`，核对已完成范围。用户要求继续建库时从记录的下一步恢复；普通任务只使用相关已完成内容。
   - **两者都不存在**：说明文档库尚未建立，读取 [仓库导航](references/repository_map.md)，再读取相关 README 章节和代码。沿用现有文档完成已授权任务，不自动创建整套 `docs/`。
   - **存在读取错误**：区分文件缺失与权限、文件损坏等问题；无法获取任务所需依据时报告具体缺口，不把错误当作“尚未建库”。
3. 用 `git status --short --branch` 识别当前工作区，保留既有修改。以当前文件为核实对象，包括未提交和新增文件，不把 `HEAD` 当作最新实现。
4. 判断此次任务是否允许写文件。问题解答与只读审查只报告漂移；实施任务同步维护其影响范围内的文档。
5. 遇到代码中的 `@project-doc` 时，在解释、审查或修改所属语义单元前读取目标章节；细则见 [锚点协议](references/anchor_protocol.md)。

技能不可用时仍按 `AGENTS.md` 的固定回复停止。技能已加载但文档库未建立，是上述入口选择问题。不得据此改写或绕过项目指令中的技能可用性门禁。

## 本仓库的文档边界

- `README.md` 与 `README.zh-CN.md` 是现有正式说明，维护相同的产品行为、命令语义、开发和发版要求；相关行为变更同步两份。
- `CONTRIBUTING.md` 与 `CONTRIBUTING.zh-CN.md` 是贡献入口；只在贡献流程或其链接受影响时更新。
- `built-in/` 承载内置资源；只对当前实际存在的资源说明评估同步影响，具体清单从文件树和嵌入入口核实。
- 本技能的实际目录为 `.codex/skills/project-doc/`；`.claude/skills` 通过 `../.codex/skills` 符号链接共享同一份内容。从任一入口修改都会影响两端，核对和编辑时按实际路径去重，保留符号链接。
- 检查 Git 跟踪与忽略状态；未跟踪或被忽略文件需直接比较修改前后的内容，不能只依赖普通 `git diff`。当前两处入口均未被忽略，可以正常纳入版本控制，但本机存在不等于已经跟踪或已在当前会话加载。
- `docs/` 建立后使用中文描述工程契约，并链接用户说明；保持 README 的双语入口和既有路径。
- 代码注释遵循 `AGENTS.md` 使用中文，CLI 提示沿用 README 的英文约定；命令名、字段名与标识符保持原样。

## 同步与交付

从受影响的入口跟进实现、调用方和测试，确认变化属于用户行为、工程契约还是局部实现。按文档维护协议更新对应说明；移动文档时一并维护目录、普通链接和代码锚点。只描述已核实的行为，不把规划、未运行的测试或未发布的工作区改动写成已完成发布。

验证范围与修改匹配：纯文档或本技能变更检查结构、链接、命名与差异；Rust 行为变更执行相关契约测试和仓库要求的检查。运行 CLI 示例验证时使用仓库现有的隔离方式，见仓库导航，避免触及真实 provider 或技能安装。

交付说明具体改动、核实依据与验证结果。若没有文档影响，简述判断即可；不创建持久化的“无影响”记录，也不为文档维护默认新增校验脚本或 CI。
